# Cómo contribuir

Este curso se construye para que otras personas puedan entender y comprobar cómo
funcionan los agentes de código. Puedes ayudar corrigiendo una errata, planteando
una duda, mejorando un ejemplo o reproduciendo un laboratorio.

## Dudas y errores

Abre una [issue](https://github.com/raulb1zkit/ENTENDIENDO-PI/issues) e indica:

- El capítulo y el paso o fragmento al que te refieres.
- Qué esperabas entender u obtener y qué ocurrió.
- Si ejecutaste un ejemplo, el sistema operativo, la versión de PI y el comando
  utilizado, con una salida mínima que permita entender el problema.

Para una duda de lectura basta con explicar qué parte no queda clara. No necesitas
tener una solución para participar.

## Proponer cambios

1. Crea un fork y una rama para tu cambio.
2. Modifica el contenido manteniendo los enlaces relativos entre documentos.
3. Revisa cómo se muestra el Markdown y comprueba los ejemplos que hayas cambiado,
   cuando sea posible hacerlo en un entorno adecuado.
4. Envía una pull request explicando el problema, la mejora y cómo la comprobaste.

Si propones un capítulo nuevo o una reorganización amplia, abre primero una issue
para acordar su encaje en el [mapa del curso](curso/00-mapa-del-curso.md).

## Criterios del material

- Escribe en español claro y explica los términos técnicos cuando aparecen.
- Distingue lo general de los agentes de lo específico de PI y su versión.
- Apoya las afirmaciones técnicas nuevas en documentación oficial, código o
  experimentos reproducibles; enlaza la fuente correspondiente.
- Indica cuándo un laboratorio necesita un proveedor y puede consumir cuota.
- Usa datos ficticios y directorios temporales para los ejemplos que lo permitan.
- Conserva las preguntas de comprensión separadas de sus respuestas para que cada
  lector pueda intentar resolverlas primero.

## Antes de compartir una salida

Revisa comandos, capturas y registros. Las sesiones pueden contener rutas privadas,
contenido de archivos, prompts, tokens y resultados de herramientas. Sustituye los
datos sensibles por ejemplos ficticios y comparte solo el fragmento necesario.

No publiques credenciales ni sesiones completas sin revisar en una issue o una
pull request.
